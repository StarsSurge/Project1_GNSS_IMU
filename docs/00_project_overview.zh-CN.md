# 项目概览

## 项目目标

本项目用于构建一个小而完整、适合面试展示的 GNSS/IMU 组合导航学习作品集。重点不是一次性写出复杂系统，而是把数学原理、代码实现、验证实验和学习笔记逐步打通。

项目方向更偏机器人定位，而不仅是传统导航。因此每个主题都应该逐步连接到：

- 机器人状态估计
- 多传感器融合
- SLAM 前端/后端思想
- ROS、rosbag 和 RViz 可视化

## 阶段规划

### 第一阶段：项目结构与基础文档

创建项目骨架，明确学习路线，准备轻量 Python 环境。

预期产出：

- `README.md` 和 `README.zh-CN.md`
- `requirements.txt`
- `docs/` 下的初始学习笔记
- `python/` 下的 Python 包骨架
- `tests/`、`data/`、`results/` 目录

### 第二阶段：合成运动与传感器数据

创建简单二维或三维运动轨迹，并生成理想/带噪声的 GNSS 和 IMU 测量。

核心学习点：

- 位置、速度、姿态、bias 和噪声
- GNSS 与 IMU 的采样率差异
- 固定随机种子保证可复现
- 绘制轨迹和传感器测量

### 第三阶段：基础 Kalman Filter

先实现一个小型线性 Kalman Filter，再进入非线性导航问题。

核心学习点：

- 预测和更新方程
- 协方差传播
- 过程噪声和观测噪声
- innovation 与一致性检查

### 第四阶段：松组合 GNSS/IMU 融合

使用 IMU 进行状态传播，用 GNSS 位置观测进行滤波更新，完成教育版 EKF 或 ESKF。

核心学习点：

- 导航状态定义
- 误差状态表示
- 离散时间传播
- GNSS 观测更新
- 加速度计和陀螺仪 bias 估计

### 第五阶段：C++ 与机器人系统集成

将关键模块迁移到 C++17，并连接机器人开发工具链。

核心学习点：

- Eigen 矩阵实现
- CMake 工程组织
- ROS message、rosbag、RViz 可视化
- Python 原型与 C++ 实现结果对比

当前第一阶段只创建马上需要的目录。`cpp/` 和 `ros/` 可以等 C++、CMake、ROS 环境准备好后再加入。

## 工程原则

- 第一版实现保持小而清晰。
- 在理解滤波行为前，优先使用合成数据。
- 用测试检查矩阵维度、简单边界情况和可复现性。
- 多画中间结果，不只看最终 RMSE。
- 明确记录坐标系、单位、重力方向和噪声模型。

## 面试导向

每个算法步骤都应该能回答：

- 状态量是什么？
- 过程模型是什么？
- 观测模型是什么？
- 噪声假设是什么？
- 哪些量是直接观测的，哪些量是估计出来的？
- GNSS 信号变差或 IMU bias 变大时会出现什么问题？
