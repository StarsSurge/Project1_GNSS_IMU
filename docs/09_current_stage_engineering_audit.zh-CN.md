# 当前阶段工程可用性审计

审计依据：仓库根目录 `AGENTS.md` 中的 `Practical Engineering Standard`。

审计范围：

- IMU 确定性/随机误差图解；
- Allan deviation 算法与真实 CSV 分析入口；
- 圆锥、划桨和旋转补偿合成实验；
- 当前已有 KF/EKF 测试回归；
- 文档、数据和结果目录的可追溯性说明。

## 1. 成熟度结论

| 模块 | 当前等级 | 结论 |
|---|---|---|
| KF/EKF Python 原型 | 验证过的教学 MVP | 有单元测试，但不是 GNSS/IMU 生产滤波器 |
| IMU 误差图解 | 教学原型 | 数学与数值趋势已验证，只使用合成数据 |
| 圆锥/划桨两子样算法 | 验证过的算法原型 | 有细积分参考和边界说明，尚未接真实 IMU 数据流 |
| Allan 核心算法 | 验证过的 MVP | 已进入 `gnss_imu` 正式模块，支持真实命名列 CSV |
| Allan 参数辨识流程 | 验证过的 MVP | 有时间戳拒绝、单位转换和审计输出，尚无真实设备闭环 |
| GNSS/IMU ESKF | 验证过的生产导向 MVP | 已有 WGS-84 传播、杆臂、NIS 门限、Joseph 更新、真实数据回放；尚非部署级 |

当前仓库没有任何模块可标记为 deployment-ready。

## 2. 本次审计发现并修复的问题

### 2.1 算法代码与图解代码混放

原 Allan 实现位于 `visual_explanations/`，不适合作为真实日志处理接口。

修复：

- 新增 `python/gnss_imu/imu_allan.py`；
- 图解脚本复用正式模块，不维护第二套公式；
- 通过 `gnss_imu.__init__` 暴露稳定入口。

### 2.2 没有真实日志入口

原阶段只能生成合成曲线，不能验证 CSV 的时间戳、单位和数据类型。

修复：

- 新增 `python/examples/analyze_imu_allan.py`；
- 支持命名列、秒/毫秒/微秒/纳秒时间戳；
- 支持 rate 和 increment 输入；
- 支持显式 SI 单位缩放；
- 输出 CSV、JSON 元数据和 PNG。

### 2.3 时间戳问题会被静默忽略

Allan 实现要求等采样，原实现没有在真实数据入口强制检查。

修复：

- 检查时间戳严格递增；
- 统计采样频率、RMS 抖动和最大间隔比；
- 丢包或抖动超过阈值时默认拒绝分析；
- 不跨间断自动插值。

### 2.4 输入失败边界不完整

原非重叠 Allan 和姿态辅助函数主要依赖 NumPy 的隐式异常。

修复：

- 拒绝 NaN、无穷值、非正采样率和非法聚类时间；
- 聚类时间映射到整数样本数后去重；
- 拒绝零范数四元数和错误维度向量；
- CSV 缺列、非有限值和错误输入类型显式报错。

### 2.5 结果只有图片，不便审计

修复：

- `allan_deviation.csv` 保存数值结果；
- `analysis_metadata.json` 保存输入约定、采样诊断、成熟度和限制；
- 图中同时显示差分对数量；
- 明确差分对数量不等于等效自由度。

### 2.6 合成结果可能被误读为真实性能

修复：

- README 和学习文档明确区分教学原型、验证过的 MVP 和部署级实现；
- 圆锥与划桨的改善倍数明确限定为理想合成实验；
- 明确仓库当前没有可追溯的真实静态 IMU 数据。

## 3. 当前验证证据

- 全项目单元及集成测试：40 项；
- 真实 CSV CLI 端到端测试：读取临时日志并检查 CSV/JSON/PNG 产物；
- 白噪声 Allan 斜率测试；
- 重叠/非重叠一致性测试；
- 时间戳间断、倒退、NaN、缺列和单位转换测试；
- 四元数/DCM 一致性；
- 圆锥和划桨交叉项结构测试；
- 三组图解脚本可重复生成。

测试通过只说明当前约定与已覆盖行为一致，不代表完成真实设备验证。

## 4. 仍未满足部署要求的项目

### 4.1 真实 IMU 数据

- 缺少设备型号、固件、量程、带宽和输出率明确的长时间静态日志；
- 缺少预热、环境温度、安装条件和振动条件记录；
- 缺少重复上电实验；
- 缺少温箱、六位置和转台标定数据。

### 4.2 Allan 工具

- 未实现自动静止检测；
- 未实现饱和、突变和异常值审计报告；
- 未实现按连续时间段自动切片；
- 未实现等效自由度及置信区间；
- 未实现斜率区间自动候选与人工确认工作流；
- 未将参数自动转换为经过单位审计的 ESKF `Qc` 配置。

### 4.3 IMU 前处理与机械编排

- 没有生产兼容的 `IMUPreprocessor` 数据结构；
- 没有温度、比例因子、非正交、安装角标定文件接口；
- 两子样算法尚未处理不等间隔、乱序、丢子样和设备固件已补偿等情况；
- 没有真实振动或高动态日志对比；
- 没有计算耗时和实时性基准。

### 4.4 GNSS/IMU ESKF

- 已实现 15 状态名义/误差状态传播、GNSS 位置更新、注入和 reset；
- 已实现地球自转、运输率、正常重力、科氏项、GNSS 杆臂和 NIS 门限；
- 已完成 dataset1 短回放、60 秒定量评估及高精/MEMS 配置路径验证；
- 仍缺在线对准、精确延迟状态更新、GNSS 速度观测、温度模型、21 状态
  比例因子在线估计、C++ 实时实现和多设备现场验证。

## 5. 下一阶段部署化验收门槛

当前已达到 verified MVP / production-oriented baseline。声称部署可用之前仍需：

1. 完成真实设备在线粗/精对准、静止检测和重启恢复。
2. 完成硬件时间同步、时延标定和延迟状态更新。
3. 加入 GNSS 速度/Doppler、状态质量和连续异常管理。
4. 加入温度、饱和、振动整流、比例因子和非正交完整处理链。
5. 在高动态、长失锁、跳点、多路径和丢包场景做故障注入。
6. 使用多套独立设备和重复上电数据做盲测，不使用 truth 辅助初始化。
7. 完成 C++ 实时实现、性能基准、确定性内存和长时间 soak test。
8. 报告一致性统计、失败案例和安全降级策略。

在真实数据可用前，合成测试用于证明实现逻辑和错误检出能力，不用于宣称
真实导航精度。
